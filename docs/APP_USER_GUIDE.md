# X2 App 使用手册

适用：本仓库手机 App、PC2 WebSocket 桥接、X2 Ultra / Agi v0.9.7。目标是人工行走、手部抓握及上肢动作复用，不包含导航。部署步骤见 [PC2 部署手册](PC2_DEPLOYMENT.md)。

## 1. 当前可用范围

| 功能 | Mock 模拟后端 | 当前 X2 后端 |
| --- | --- | --- |
| 连接、控制租约、人工速度与模式指令 | 模拟 | 沿用现有官方 MC 接口 |
| 14 个臂关节＋左右手各 10 个状态录制 | 模拟反馈 | 真实反馈，只读采样 |
| 轨迹保存、列表、改名、删除 | 支持 | 支持 |
| 位置预设编辑、保存、读取双手位置 | 支持 | 支持 |
| 手部位置目标/抓握预设执行 | 模拟 | 未开放：MC 控制权未确认 |
| 轨迹重复播放、速度、暂停、继续 | 模拟 | 未开放：MC 动画执行与停止未确认 |
| 卸力拖动示教、自动交接检测 | 不提供 | 不提供 |

连接后页面上方显示后端说明。真机执行按钮灰色是能力限制，不是网络故障。录制状态不需要进入 `Develop_MC`；不要强掰仍上电的手指或机械臂。Mock 的执行成功不能用作真机验收。

## 2. 连接与解锁

1. 手机、App 开发电脑及 PC2 网络互通，先按部署手册启动桥接。
2. 真机地址填 `ws://10.0.1.41:8765`，点击“连接”。Mock 地址使用运行桥接的电脑 IP，不能误填机器人的地址。
3. 检查后端说明、连接状态和机器人状态。初始为 `IDLE`。
4. 需要发送控制命令或录制时点击“进入 TELEOP”。这只是桥接解锁，不代表机器人已站稳，也不会自动切换机器人运动模式。

同一时刻只允许一台 App 控制。收到“已有另一台设备占用控制权”时，先让原设备退出。收到“不支持的消息类型”或能力说明未显示时，核对 App 与桥接版本，不要靠重新切换机器人状态解决。

## 3. 人工行走与携带

“移动控制”页：左摇杆控制前后/横移，右摇杆控制转向。服务端限制速度；松开摇杆发送零速度。运动模式按钮继续调用官方 MC，不参与轨迹录制。

携带阶段不播放或保持手臂轨迹。“轨迹录制”页的“单手携带 · 人工行走”只是切换到移动页，不自动进入行走模式、不发送抓握、不证明已抓稳。原有名为“单手携带”的轨迹仍保存在列表中。

现场流程为：确认抓握 → 官方人工行走 → 到位停车站稳 → 双手接持/递出 → 操作员确认接稳 → 松手 → 收回 → 官方人工离场。当前版本尚未完成手部执行及上肢回放接入，不能直接用本 App 完成整个真机颁奖流程。

## 4. 录制并复用轨迹

1. 用官方支持的方式准备机器人的动作。录制按钮本身不会驱动、卸力或移动机械臂。
2. 进入“轨迹录制”页并解锁，填写一个未使用的名称，例如“单手抓取”。
3. 设置采样率，范围 1–100 Hz，初次建议 20 Hz。
4. 点击“开始上肢状态录制”。服务端先检查完整的 14＋10＋10 状态；尚未收到状态时会报错，不会创建空轨迹。
5. 按官方允许的操作方式让机械臂运动，观察帧数是否增加。录制只采集臂和双手的位置、速度、力矩字段；不录制腿、腰或底盘。
6. 点击“停止并保存录制”，确认列表出现该轨迹。页面显示帧数、时长和三组关节数量。
7. 用“改名”保存新名称；“删除”需要弹窗确认且不可撤销。同名录制/保存不会覆盖旧数据。

状态缓存超过 0.5 秒或反馈不完整时不写入该采样，页面显示提示。100 Hz 是采样目标，不保证机器人反馈或手机状态刷新达到 100 Hz。App 进度约每 0.2 秒刷新。

录制/播放期间，桥接把自己的底盘速度输出限制为零，并拒绝通过本 App 切换运动模式；这不等于禁止其他官方控制器发命令。录制时手部目标可以用于模拟制作动作，真机手部执行仍受能力限制。

保存位置：PC2 的 `/home/run/.x2_ps5_teleop/trajectories.json`。只有停止并保存才落盘；切后台、断线、退出 TELEOP 或心跳超时会取消活动，未保存录制会丢弃，不会删除已保存轨迹。

### 重复播放（当前在 Mock 中验证）

选择 0.25x / 0.5x / 1x / 2x，然后点击列表里的“播放”。同一条轨迹可在完成后反复播放；播放不会删除或改写原始数据。

“暂停”保留播放位置，“继续”接着播放，“停止”取消当前播放。播放过程中不能同时发送手部目标、开始第二条轨迹或切换运动模式。协议速度范围为 0.01–4x。

X2 后端当前禁用回放，原因是旧固件的 MC 动画导入及可靠停止机制未确认，不是轨迹记录方式有问题。不能删除状态检查或另起 HAL 发布程序来播放。

## 5. 灵巧手位置预设

进入“灵巧手预设”页。新页面只使用位置，不把旧接口中尚未确认的速度、加速度、力度字段作为控制功能。

1. 选择左手或右手，点击“读取当前双手位置”，将实际反馈读入编辑器。此操作不会驱动电机。
2. 每只手有 10 个槽，单位 rad，保留反馈的槽位顺序和符号。不要额外镜像左手前三个值。
3. 输入目标位置。±π rad 是输入编辑边界，不是关节硬件限位；数值是否可执行仍需单独标定。
4. 填写预设名称，例如“右手抓奖状”“左手接持”“右手松开奖状”。点击“保存新预设”只保存，不执行。
5. 松手预设勾选“执行前确认选手已接稳”。执行时必须点击弹窗里的“已接稳，执行”；取消不会下发目标。
6. “载入编辑”读取已保存参数，不发送目标；编辑后用新名称保存。“改为输入名称”将该条预设改为上方名称框的内容。

“发送所选手的位置目标”和预设“执行”只作用于所选手，不自动发另一只手目标。当前只有 Mock 开放执行。按钮成功表示目标已发送，不是力觉确认抓稳。断线和软件停止都不会自动张开手。

预设保存在 `/home/run/.x2_ps5_teleop/hand_poses.json`，与轨迹文件独立，不会将已有轨迹转换成手部预设。没有提供通用的零值张开/0.8 抓握按钮，因为这些数值不是经过标定的奖状抓握姿态。

## 6. 停止与常见问题

- **App 急停**：取消本桥接活动、发送底盘零速度并锁存。它不是物理急停，不会切断电机电源，也不能保证终止其他控制器启动的动作。
- **恢复**：现场确认后点击“清除软件急停锁存”，再单独进入 TELEOP。清除不会自动解锁。
- **心跳超时**：录制和播放期间也生效；约 0.4 秒未收到有效控制心跳进入 TIMEOUT。恢复连接后重新解锁。
- **手部执行灰色**：v0.9.7 原生 MC 控制权未移交，保存/编辑仍可用。
- **录制提示反馈缺失**：检查官方状态话题、ROS 环境和网络；重试前不要迁移系统状态。
- **读取的位置超过编辑范围**：保留原始轨迹，不要强行裁剪后当作相同姿态。需核对槽位、单位和硬件限位。
- **轨迹未出现在列表**：点击刷新，核对桥接使用的是 `run` 用户以及正确的数据路径。
