# X2 App 使用手册

适用：本仓库手机 App、PC2 WebSocket 桥接、X2 Ultra / Agi v0.9.7。目标是人工行走、手部抓握及上肢动作复用，不包含导航。部署步骤见 [PC2 部署手册](PC2_DEPLOYMENT.md)。

## 1. 当前可用范围

| 功能 | Mock 模拟后端 | 当前 X2 后端 |
| --- | --- | --- |
| 连接、控制租约、人工速度与模式指令 | 模拟 | 沿用现有官方 MC 接口 |
| 14 个臂关节＋左右手各 10 个状态录制 | 模拟反馈 | 真实反馈，只读采样 |
| 轨迹保存、列表、改名、删除 | 支持 | 支持 |
| 位置预设编辑、保存、读取双手位置 | 支持 | 支持 |
| 手部五参数、位置目标/抓握预设执行 | 模拟 | 已恢复原 HAL 手部路径；需现场核验抓握 |
| 轨迹重复播放、速度、暂停、继续 | 模拟 | 已接入独立 MC 后端；无报告时为有人值守测试模式 |
| 卸力拖动示教、自动交接检测 | 不提供 | 不提供 |

连接后页面上方显示后端说明。真机上肢回放按钮灰色是能力限制，不是网络故障。手部发送需进入 TELEOP，且不能处于准备、播放、暂停中、已暂停、停止中或停止未确认状态。录制状态不需要进入 `Develop_MC`；不要强掰仍上电的手指或机械臂。Mock 的执行成功不能用作真机验收。

## 2. 连接与解锁

1. 手机、App 开发电脑及 PC2 网络互通，先按部署手册启动桥接。
2. 真机地址填 `ws://10.0.1.41:8765`，点击“连接”。Mock 地址使用运行桥接的电脑 IP，不能误填机器人的地址。
3. 检查后端说明、连接状态和机器人状态。初始为 `IDLE`。
4. 需要发送控制命令或录制时点击“进入 TELEOP”。这只是桥接解锁，不代表机器人已站稳，也不会自动切换机器人运动模式。

同一时刻只允许一台 App 控制。收到“已有另一台设备占用控制权”时，先让原设备退出。收到“不支持的消息类型”或能力说明未显示时，核对 App 与桥接版本，不要靠重新切换机器人状态解决。

## 3. 人工行走与携带

“移动控制”页：左摇杆控制前后/横移，右摇杆控制转向。服务端限制速度；松开摇杆发送零速度。运动模式按钮继续调用官方 MC，不参与轨迹录制。

携带阶段不播放或保持手臂轨迹。“轨迹录制”页的“单手携带 · 人工行走”只是切换到移动页，不自动进入行走模式、不发送抓握、不证明已抓稳。原有名为“单手携带”的轨迹仍保存在列表中。

现场流程为：确认抓握 → 官方人工行走 → 到位停车站稳 → 双手接持/递出 → 操作员确认接稳 → 松手 → 收回 → 官方人工离场。未加载报告时 App 会明确显示现场测试模式；此模式只能用于空载、物理急停有人值守的验证，不能当作完整颁奖流程已验收。

## 4. 录制并复用轨迹

1. 先明确一个**已确认可用的官方操作**能产生要录的动作。录制只是采集实际反馈，不是拖动示教，不会自动创造“双手捧出”姿态；任意新姿态仍需明确可用的官方工具或另行实现并验证姿态编辑，不能假定存在官方示教功能。不要强掰上电关节。
2. 进入“轨迹录制”页并解锁，填写一个未使用的名称，例如“单手抓取”。
3. 设置采样率，范围 1–100 Hz，初次建议 20 Hz。
4. 点击“开始上肢状态录制”。服务端先检查完整的 14＋10＋10 状态；尚未收到状态时会报错，不会创建空轨迹。
5. 按官方允许的操作方式让机械臂运动，观察帧数是否增加。录制只采集臂和双手的位置、速度、力矩字段；不录制腿、腰或底盘。
6. 点击“停止并保存录制”，确认列表出现该轨迹。页面显示帧数、时长和三组关节数量。
7. 用“改名”保存新名称；“删除”需要弹窗确认且不可撤销。同名录制/保存不会覆盖旧数据。

状态缓存超过 0.5 秒或反馈不完整时不写入该采样，页面显示提示。100 Hz 是采样目标，不保证机器人反馈或手机状态刷新达到 100 Hz。App 进度约每 0.2 秒刷新。

录制/播放期间，桥接把自己的底盘速度输出限制为零，并拒绝通过本 App 切换运动模式；这不等于禁止其他官方控制器发命令。录制时可以发送手部参数目标，采集到的是反馈状态；应检查实际手指响应，发送成功不等于抓稳。

保存位置：PC2 的 `/home/run/.x2_ps5_teleop/trajectories.json`。只有停止并保存才落盘；切后台、断线、退出 TELEOP 或心跳超时会取消活动，未保存录制会丢弃，不会删除已保存轨迹。

### 保存后的播放（Mock 可用；真机须先验收）

现场验收并由维护人员加载验收配置后，先用已确认的官方操作准备稳定站立和轨迹起始姿态，再进入 TELEOP。先在列表中选择轨迹，再点击上方“播放：轨迹名”。未连接、未进入 TELEOP 或未加载完整验收配置时播放按钮保持禁用并显示原因。默认 0.25x；Mock 可选 0.25x / 0.5x / 1x / 2x，真机不超过报告限制（当前最高 0.25x），超限按钮不可用。同一条轨迹可在完成后反复播放；播放不会删除或改写原始数据。

MC “暂停”先生成当前反馈姿态的恒定动画，等待状态序列及稳定反馈确认后才显示“已暂停”。“继续”从估算进度生成剩余片段并再次校验起点；与实际姿态不匹配会拒绝，不能强制继续。“停止”同样等待实际反馈，不以服务成功为依据。协议速度范围为 0.01–4x，真机还受报告限制。

播放包含左右手各 10 个主动轴，能重放录制时的手指动作。整个活动期间禁止单独发送手部参数、位置或预设，暂停后也不允许。需要等待选手接稳时，将动作拆成“递出轨迹完成 → 人工确认接稳 → 独立松手预设 → 收回轨迹”；不要把人工确认时机交给自动计时。

真机 X2 Bridge 启动后会开放回放；没有 commissioning 报告时页面显示醒目的现场测试警告并采用保守限制。加载报告后增加远端库/配置哈希核对并标记为已验收模式。代码采用 500 Hz 上肢 CSV → soc0 → 官方 MC，不使用逐帧 HAL 手臂发布，保留原状态保护。

| 状态 | 含义与操作 |
| --- | --- |
| preparing | 转换、核验、上传或等待 MC 启动；可停止 |
| playing | 正在执行；进度为估算，可暂停或停止 |
| pausing | 正在请求保持并等反馈，不能视为已停 |
| paused | 已确认保持；可继续或停止，其他运动仍互锁 |
| stopping | 停止处理中，继续等反馈 |
| stop_failed | **停止未确认**；使用现场物理急停、排查，按钮可重试停止；不能清急停或重连来绕过互锁 |
| completed / error | 完成或错误；查看错误内容；停止未确认一定显示 stop_failed |

MC 启动/中断有过渡，显示进度并非机器人精确帧号。软件急停、退 TELEOP、断连和超时会请求相同停止流程，但 PC2 崩溃或 PC2↔MC 通信丢失可能使 MC 继续已加载动画，不能替代物理急停。

## 5. 灵巧手参数与位置预设

进入“灵巧手预设”页，默认打开“旧版五参数”。选择左/右手，按之前验证有效的数值拖动每槽的位置、速度、加速度、减速度、effort 滑条，进入 TELEOP 后点击“发送所选手的参数目标”。只发送一帧到所选手，另一手数组为空。左右手编辑值独立保留，切页不会自动发送。

旧版输入范围：位置 −1～1、速度 0～1、加/减速度 0～10、effort −1～1。保留旧版坐标转换：左手前三槽位置在发送时取反，其余原样发送。空值、非有限数和越界值均拒绝。范围是应用输入约束，不是硬件限位；各字段是否生效由手部固件决定，不能将 effort 当作已验证的力控或卸力功能。初始零值不是经过标定的张开姿态。五参数编辑值不单独持久化。所有数值输入框已替换为滑条，步长约 0.001；预设名称仍使用文字输入框。反馈超出范围时显示原值及提示，不会因为滑条只能显示到端点就自动改写反馈。

握住奖状：先用之前有效的参数在空载下小幅调整，确认槽位与运动方向，再由现场人员放入奖状、逐步合拢并检查是否抓稳。不要照抄通用数值作为奖状抓握姿态。确认合适后切换“反馈位置与预设”，读取当前位置并保存“右手抓奖状”等位置预设，便于下次调用。这里保存的是实际位置，不保存五参数。

两种编辑页均按下表标注主动自由度（槽号为接口的 0 起始索引）。中指没有独立侧摆；其余耦合关节不会另加命令槽。名称来自官方 HAL 索引表，并与本机 `animation_player.yaml` 的顺序交叉核对。

| 槽 | 位置／自由度 | 实机轴名后缀 |
| --- | --- | --- |
| 0 | 拇指根部旋转 | thumb_roll_joint |
| 1 | 拇指侧摆（外展／内收） | thumb_abad_joint |
| 2 | 拇指掌指关节屈伸 | thumb_mcp_joint |
| 3 | 食指侧摆（外展／内收） | index_abad_joint |
| 4 | 食指屈伸 | index_pip_joint |
| 5 | 中指屈伸 | middle_pip_joint |
| 6 | 无名指侧摆（外展／内收） | ring_abad_joint |
| 7 | 无名指屈伸 | ring_pip_joint |
| 8 | 小指侧摆（外展／内收） | pinky_abad_joint |
| 9 | 小指屈伸 | pinky_pip_joint |

“反馈位置与预设”的操作：

1. 选择左手或右手，点击“读取当前双手位置”，将实际反馈读入编辑器。此操作不会驱动电机。
2. 每只手有 10 个槽，单位 rad，保留反馈的槽位顺序和符号。不要额外镜像左手前三个值。
3. 拖动位置滑条设置目标；当前值和范围显示在滑条旁。拖动只编辑，点击发送才执行。±π rad 是输入编辑边界，不是关节硬件限位；数值是否可执行仍需单独标定。
4. 填写预设名称，例如“右手抓奖状”“左手接持”“右手松开奖状”。点击“保存新预设”只保存，不执行。
5. 松手预设勾选“执行前确认选手已接稳”。执行时必须点击弹窗里的“已接稳，执行”；取消不会下发目标。
6. “载入编辑”读取已保存参数，不发送目标；编辑后用新名称保存。“改为输入名称”将该条预设改为上方名称框的内容。

“发送所选手的位置目标”和预设“执行”只作用于所选手，不自动发另一只手目标。X2 已恢复发送，沿用 `/aima/hal/joint/hand/command`，未另装 SDK。按钮成功表示目标已发送，不是力觉确认抓稳。断线和软件停止都不会自动张开手。

预设保存在 `/home/run/.x2_ps5_teleop/hand_poses.json`，与轨迹文件独立，不会将已有轨迹转换成手部预设。位置预设页没有提供通用的零值张开/0.8 抓握按钮，因为这些数值不是经过标定的奖状抓握姿态。

官方 MC 仍可能写手部目标；本次恢复依据是本机旧版已可工作的现场反馈，不代表所有运动模式都已验证。若手指回弹、目标被覆盖或抖动，停止该次操作并记录当时模式；不要提高发布频率争抢，也不要停掉全身 MC。灵巧手卸力仍未确认。

## 6. 停止与常见问题

- **App 急停**：取消本桥接活动、发送底盘零速度并锁存。它不是物理急停，不会切断电机电源，也不能保证终止其他控制器启动的动作。
- **恢复**：现场确认后点击“清除软件急停锁存”，再单独进入 TELEOP。清除不会自动解锁。
- **心跳超时**：录制和播放期间也生效；约 0.4 秒未收到有效控制心跳进入 TIMEOUT。恢复连接后重新解锁。
- **手部执行灰色**：检查是否已连接更新后的桥接、进入 TELEOP，以及是否还有正在播放或暂停的轨迹。
- **录制提示反馈缺失**：检查官方状态话题、ROS 环境和网络；重试前不要迁移系统状态。
- **读取的位置超过编辑范围**：保留原始轨迹，不要强行裁剪后当作相同姿态。需核对槽位、单位和硬件限位。
- **轨迹未出现在列表**：点击刷新，核对桥接使用的是 `run` 用户以及正确的数据路径。
